# ADR-0002: Автоматическое обновление CHANGELOG через Pull Request (соблюдение INT-L3)

## Статус
Принято (2026-08-14)

## Контекст
При настройке автоматического обновления `CHANGELOG.md` и `SHA256SUMS` при публикации релиза, первоначальная попытка прямого `git push` от имени `github-actions[bot]` была заблокирована правилами защиты ветки `master` (Repository Ruleset). 

Ruleset требовал:
1. Коммиты должны иметь верифицированную криптографическую подпись.
2. Изменения должны вноситься только через Pull Request.
3. Перед слиянием должны быть пройдены статус-чеки (Kon-Matrix L1 Verification).

Попытка добавить бота в список исключений (bypass list) противоречила духу методологии KON-MATRIX, так как создавала "слепую зону" в защите ветки.

## Решение
Использовать GitHub Action `peter-evans/create-pull-request@v6` для инициации процесса обновления. 

Вместо прямого пуша в `master`, workflow теперь:
1. Создаёт временную ветку (например, `auto/changelog-v0.3.0`).
2. Коммитит в неё обновлённые `CHANGELOG.md` и `SHA256SUMS`.
3. Автоматически создаёт Pull Request в ветку `master`.
4. Запускает на этой ветке все проверки CI/CD.
5. Ожидает ручного одобрения и слияния (Merge) разработчиком.

## Обоснование (Trade-offs)

**Преимущества:**
- ✅ **Полное соблюдение INT-L3:** История `master` остаётся неизменяемой и содержит только подписанные коммиты слияния.
- ✅ **Прозрачность (TRA-L3):** Каждое автоматическое изменение проходит через видимый процесс ревью.
- ✅ **Безопасность:** Нет необходимости ослаблять правила защиты ветки (Ruleset) для автоматизации.
- ✅ **Проверка:** Изменения автоматически валидируются сканером `scanner-l1.py` перед тем, как попасть в основную ветку.

**Компромиссы:**
- ⚠️ Процесс релиза требует одного дополнительного ручного действия (нажатия кнопки "Merge") от разработчика. Это добавляет ~1-2 минуты к времени обновления, но является приемлемой и необходимой платой за гарантированную целостность репозитория уровня L3.
