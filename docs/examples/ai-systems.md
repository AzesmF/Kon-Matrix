# Пример адаптации: AI-системы

**Ветвь от Ствола KON-MATRIX v2.0**
**На основе RFC v1.1**

Этот документ показывает, как универсальные критерии Матрицы Конов применяются к системам искусственного интеллекта.

---

## Какие артефакты собирать

| Кон | Уровень | Артефакт для AI-систем |
|---|---|---|
| INT | L1 | Файл контрольных сумм весов модели и датасета (`model_hashes.json`) |
| INT | L2 | Неизменяемый журнал обучения (training log) с версионностью датасетов |
| INT | L3 | Подписанный SBOM, содержащий хеши весов и датасета; проверка при загрузке модели в рантайме |
| PUR | L1 | Манифест компонентов: модель, датасет, пайплайн препроцессинга, внешние API |
| PUR | L2 | Отчёт статического анализа кода пайплайна + отчёт о проверке модели на известные атаки |
| PUR | L3 | Оценка uncertainty для каждого вывода; отчёт о тестировании на состязательные атаки (adversarial) |
| EVO | L1 | CHANGELOG с указанием версий модели и изменений в данных |
| EVO | L2 | ADR с обоснованием выбора архитектуры модели и отвергнутых альтернатив |
| EVO | L3 | Документированная стратегия A/B тестирования и плавного переключения между версиями модели без деградации сервиса |
| TRA | L1 | Логи инференса с временной меткой, ID запроса и версией модели |
| TRA | L2 | Дашборд с метриками качества модели (accuracy, latency, drift) в реальном времени |
| TRA | L3 | Экспорт всех данных, связанных с конкретным запросом пользователя: вход, выход, uncertainty, версия модели |

---

## Как интерпретировать критерии

- **INT-L3:** При загрузке модели в рантайм её хеш сравнивается с хешем в подписанном SBOM. Несовпадение — модель не запускается.
- **PUR-L3:** Каждый вывод модели сопровождается оценкой uncertainty; если uncertainty выше порога — вывод помечается флагом для ручной проверки.
- **EVO-L3:** Перед полным переходом на новую версию модели проводится A/B тест: 5% трафика идёт на новую версию, метрики сравниваются.

## Ожидаемый отчёт

| Кон | L1 | L2 | L3 |
|---|---|---|---|
| Целостность | ✅ `model_hashes.json` присутствует | ✅ Training log неизменяем | ✅ SBOM проверяется при загрузке |
| Чистота | ✅ Манифест компонентов | ✅ Сканирование чистое | ✅ Uncertainty-оценка + adversarial тесты |
| Становление | ✅ CHANGELOG моделей | ✅ ADR по архитектуре | ✅ A/B тестирование работает |
| Прозрачность | ✅ Логи структурированы | ✅ Дашборд качества | ✅ Экспорт данных запроса |
