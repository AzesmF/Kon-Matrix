# Пример адаптации: AI-системы

**Ветвь от ствола KON-MATRIX v2.0**
**С учётом RFC v1.1**

Этот документ показывает, как универсальные критерии матрицы применяются к системам искусственного интеллекта.

---

## Какие проверяемые объекты собирать

| Принцип | Уровень | Проверяемый объект для AI-систем |
|---|---|---|
| Целостность | L1 | Файл контрольных сумм весов модели и датасета (`model_hashes.json`) |
| Целостность | L2 | Неизменяемый журнал обучения (training log) с версионностью датасетов |
| Целостность | L3 | Подписанный SBOM, содержащий хеши весов и датасета; проверка при загрузке модели в рантайме |
| Чистота | L1 | Манифест компонентов: модель, датасет, пайплайн препроцессинга, внешние API |
| Чистота | L2 | Отчёт статического анализа кода пайплайна + отчёт о проверке модели на известные атаки |
| Чистота | L3 | Оценка uncertainty для каждого вывода; отчёт о тестировании на состязательные атаки (adversarial) |
| Развитие | L1 | CHANGELOG с указанием версий модели и изменений в данных |
| Развитие | L2 | ADR с обоснованием выбора архитектуры модели и отвергнутых альтернатив |
| Развитие | L3 | Документированная стратегия A/B тестирования и плавного переключения между версиями модели без деградации сервиса |
| Прозрачность | L1 | Логи инференса с временной меткой, ID запроса и версией модели |
| Прозрачность | L2 | Дашборд с метриками качества модели (accuracy, latency, drift) в реальном времени |
| Прозрачность | L3 | Экспорт всех данных, связанных с конкретным запросом пользователя: вход, выход, uncertainty, версия модели |

---

## Как интерпретировать критерии

- **Целостность L3:** При загрузке модели в рантайм её хеш сравнивается с хешем в подписанном SBOM. Несовпадение — модель не запускается.
- **Чистота L3:** Каждый вывод модели сопровождается оценкой uncertainty; если uncertainty выше порога — вывод помечается флагом для ручной проверки.
- **Развитие L3:** Перед полным переходом на новую версию модели проводится A/B тест: 5% трафика идёт на новую версию, метрики сравниваются.

## Ожидаемый отчёт

| Принцип | L1 | L2 | L3 |
|---|---|---|---|
| Целостность | ✅ `model_hashes.json` присутствует | ✅ Training log неизменяем | ✅ SBOM проверяется при загрузке |
| Чистота | ✅ Манифест компонентов | ✅ Сканирование чистое | ✅ Uncertainty-оценка + adversarial тесты |
| Развитие | ✅ CHANGELOG моделей | ✅ ADR по архитектуре | ✅ A/B тестирование работает |
| Прозрачность | ✅ Логи структурированы | ✅ Дашборд качества | ✅ Экспорт данных запроса |
